## What Your Crawlers Actually Are (Technically)

Your imagination was right about what they SHOULD do. Your code delivers about 30% of that vision. Here's the exact gap:

### Project State Crawler (PSC)
**What it really is:** A regex-based static parser that walks your file tree and extracts named symbols — functions, classes, routes, imports — comparing them snapshot-to-snapshot to detect structural drift.

**What it is NOT:** It has no semantic understanding. It doesn't know that `handleAuthLogin()` and `verifyUserSession()` are related. It doesn't understand architecture, design patterns, or user intent. Drift detection means "this function moved 40 lines" — not "this function became insecure."

**Verdict:** Solid foundation. Missing the semantic layer on top.

### Suggested Jobs Crawler
**What it really is:** Reads blame/criticism records from the DB, OR cycles through 11 hardcoded protocols that run SQL queries and pattern-match against existing job records. Generates `job_records`. Zero LLM involvement.

**What it is NOT:** It doesn't read your actual source code to decide what jobs are needed. It reads database rows about previous jobs and generates derivative jobs. It's a jobs-from-jobs machine, not a code-to-jobs machine.

**Verdict:** Circular without the semantic crawler layer feeding it real signal.

### Gap Analysis
**What it really is:** Five sub-agents that are SQL aggregators. They count things in the database — how many buildtags failed, how many devtags went missing, how many tool criticisms exist. All heuristics, no reasoning.

**What it is NOT:** Real architectural gap analysis. It can't say "you have no input validation on this API route" because it never reads the route code.

**Verdict:** The structure is correct. The intelligence is placeholder.

### God Factory Idle Scanner
**What it really is:** A regex linter — walks files looking for `TODO`, `console.log`, `// FIXME`, `async` without `catch`. Writes `idle_suggestions`.

**What it is NOT:** Anything close to autonomous architectural reasoning. It's grep dressed up as AI.

**Verdict:** Replace with a real static analysis pass + LLM-powered reflection pass.

The crawlers produce data. The God Factory barely reads it. The pipeline is like having employees file reports that nobody opens.

## The Memory Layer

The memory service is well-built. But:
1. **Not injected into God Factory context** — when the agent starts, it doesn't load the project's memory notes into its system prompt. It's there but not used.
2. **No cross-reference with tags** — a memory note about a file has no link to the devtags in that file. They're parallel systems that ignore each other.
3. **No semantic search** — memory search is `LIKE '%keyword%'` SQL. GitHub Copilot uses vector embeddings — it finds relevant context by *meaning*, not exact word match. This is the biggest practical gap.
4. **No forgetting** — it grows to 10k notes with no pruning by quality/relevance.

## The Tag System (Devtags / Buildtags / Plantags)

Your imagination of a tag taxonomy is actually a smart RAG-adjacent approach — cheaper than full code ingestion, faster than Copilot's full-file embedding. But it's missing layers:

| What you have | What it does | What's missing |
|---|---|---|
| **Devtags** | Structural symbols (function names, classes) | Semantic descriptions — *what does this function DO*, not just its name |
| **Plantags** | Planned work items | Almost nothing creates them automatically. They need to flow from conversation intent to code locations |
| **Buildtags** | Execution records per agent iteration | Nobody reads them to make routing decisions |
| ❌ **Semantictags** | — | LLM-generated description of each symbol — enables semantic search |
| ❌ **Qualitytags** | — | Test coverage %, complexity score, last-failure-count per symbol |
| ❌ **Modeltags** | — | Which model performed best on this file/symbol type |
| ❌ **Contexttags** | — | What other symbols this one needs to be modified safely |

**vs. full code ingestion:** Your approach is correct in principle — cheaper, faster, token-efficient. But right now the devtags are too shallow because they're name-only with no semantic layer. Adding semantic embedding (a single local model embedding pass per symbol) would make this competitive with Copilot's approach.
