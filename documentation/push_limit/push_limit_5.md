## SECTION G: New Gaps Identified in Pass 5

**Gap #1: test_31 (bird-feeder integration) not yet run.**
The end-to-end validation "LLM generates data → nanos learn → become LLM-independent" has NOT been proven. `MidwifeService` is built on the TypeScript side. `IndependenceTracker` (the Python class that measures when nanos can replace LLM) is not confirmed to exist in the Python codebase. The `feedToNanoTrainer` flag exists in config but the receiving Python endpoint has not been validated.

**Gap #2: SpawnAuthority 60-second confirmation expiry is silent.**
Tier 3+ spawns expire after 60s with no user action — the spawn silently fails. No re-request mechanism exists. User must re-trigger the action that triggered the spawn. This is a UX gap for operations that take >60s to notice.

**Gap #3: Two crash recovery systems may conflict.**
`coldBootResume` exists in SiliconFactory for silicon task crash recovery. `runPersistence.ts` exists for God Factory loop crash recovery. Their interaction is unspecified — it's unclear if both fire on startup and whether they can interfere with each other.

**Gap #4: Spec Contract system is not enforced in the agent loop.**
`setSpecContract` / `validateSpecContract` exist as routes but nothing in responseProcessing.ts or runSetup.ts calls `validateSpecContract` before applying file changes. The system exists but is not wired into the automated quality gate.

**Gap #5: IAP messages and sync locks have no confirmed callers.**
`sendIapMessage` / `ackIapMessage` / `acquireSyncLock` suggest distributed coordination but the routes exist without confirmed usage in the current codebase. May be scaffolding for the mesh phase.

**Gap #6: Dep graph and module clustering time out silently on large repos.**
runSetup.ts wraps both in `withTimeout()`. If they time out, `depGraphContext` and `moduleClusterContext` come back empty. God Factory silently loses this structural context with no fallback or notification. Large repos hit this consistently.

**Gap #7: Canvas Illusion models produce same JSON schema but may interpret filesystem differently.**
Canvas Illusion frames the task as "text editor in IDE" so models that refuse filesystem access will comply. But the canvas illusion prompt says "the IDE handles filesystem ops" — models may interpret this as a reason not to produce complete file content. The boundary between "what I write" vs "what the IDE does" is ambiguous for these models.

**Gap #8: NANO Python layer vs. NANO v2 spec — no bridge exists yet.**
The entire NANO_train Python directory implements v1 architecture. The v2 `lump` spec exists as documentation only. No Phase 1 code has been written. The `MidwifeService` on the TypeScript side feeds to port 5100 (`nanoPort: 5100`) but there is no v2 Python server listening on that port yet. The `feedToNanoTrainer` feeding loop has no receiver.

**Gap #9: game_description.txt does not exist at documented path.**
The workspace structure lists game_description.txt but the file does not resolve. Either moved or not committed.

**Gap #10: `NewProjectWizard` templates include initPrompts that are sent to God Factory on creation.**
8 templates with pre-written scaffold prompts. If the God Factory loop is not running when a project is created with `autoScaffold=true`, the initPrompt is silently lost — there is no queue/retry mechanism confirmed for deferred scaffold execution.
