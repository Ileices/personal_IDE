THE ARCHITECTURE IN TWO SENTENCES

The Personal IDE is an agentic IDE where every operation is mediated by a unified
tag language. Nano Sea replaces the external LLM dependency — agents still issue
the same queries and receive the same response format, but increasingly those
responses come from the local nano swarm rather than from cloud models.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

THE CORE INSIGHT

Current agent loop:
  Agent → Query → Cloud LLM → Response → Tag Validator → Action

Post-nano loop:
  Agent → Query → Model Router → Nano Sea OR Cloud LLM → Response → Tag Validator → Action

The router decides: is this query workload suitable for the nano sea, or should it
escalate to a cloud model? Early on, most things escalate. Over time, as nanos
specialize and the sea scales, more work stays local. Eventually, the sea becomes
the primary executor and cloud models become the exception (backfill, edge cases,
major architecture changes).

The tag validator is UNCHANGED. The response format is UNCHANGED. The only change
is where the response comes from.

WHY THIS MATTERS (THE MATH WORKS)

Nano Sea v2 is not speculative. It is grounded in 30 validated experiments proving:

1. Multiple small experts (soft-k routing on a swarm) beat one large model by 8-10%
   at the same parameter count.
2. Soft differentiable routing works better than hard top-k.
3. Expert crosstalk (cross-attention between nanos in the same layer) improves results.
4. Chromatic routing (RBY-simplex navigation) gives interpretable expert positions.
5. Touch tensor logging (which nanos activate for which inputs) provides fitness signals.
6. Cosmic cycles (train → compress → deposit → rebuild) improve models across iterations.
7. Deposit-guided initialization beats random initialization.
8. Three swarm layers is optimal at ~500K total parameters.

These are tested facts. The research package includes all 30 test scripts and results.

THE NANO ARCHITECTURE IN 30 SECONDS

Query → Shared Embedding → SwarmLayer1 → SwarmLayer2 → SwarmLayer3 → Output Head → Response

SwarmLayer = 2000-5000 tiny nanos (1K-50K params each) + ChromaticIndex router
  • Router selects top ~8 nanos per token (soft, learnable k)
  • Each nano processes query in parallel
  • Expert crosstalk: nanos attend to each other (optional, learned gate)
  • Outputs weighted and summed

Key numbers:
  • Total params: ~500K (typical)
  • Nanos activated per token: ~8
  • Effective capacity: 8 nanos × 3 layers × 30K params = much larger than 500K suggests
  • Inference speed: 10-100x faster than 7B-70B cloud models
  • Training cost: thousands vs millions

THE SWARM LAYER IN DETAIL

1. Query embedding comes in (d_model dimensions)
2. ChromaticIndex router scores all nanos using RBY-simplex positions
3. Soft-k routing selects top ~8 nanos (differentiable, learned k per query type)
4. Each selected nano processes query (parallel)
5. Expert crosstalk: nanos exchange information via cross-attention
6. Outputs weighted and summed
7. Result → next layer or output head

RBY Simplex is geometric: R=complexity/abstraction, B=domain, Y=style. Nanos
specialize and occupy positions. Router uses Aitchison distance for similarity.

Routing is learned. Crosstalk is learned. Early: many activations, high crosstalk.
Over time: tight specialization, minimal crosstalk (unless beneficial).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

COSMIC CYCLES: HOW NANOS IMPROVE OVER TIME

1. TRAIN: Run sea on real workloads. Nanos learn. Touch tensor logs activations.
2. COMPRESS: Dead nanos die. Weak nanos pruned. New nanos spawn in gaps.
3. DEPOSIT: High-performers serialized to disk (deposits are searchable).
4. REBUILD: New nanos warm-start from deposits (beats random by ~25%).
Then repeat.

After K cycles: sea has iterated K times, specializations deepened, weak performers
removed, new entrants have prior knowledge. Performance compounds.

INTEGRATION INTO AGENT QUERIES

Today: Query has explicit model="gpt-4o"
Tomorrow: Query has model_routing with primary=nano_sea, fallback=gpt-4o, routing_hints

Router decides: nano_sea or cloud based on:
  • Query type (code_gen, reasoning, test, refactor, etc)
  • Complexity
  • Safety level
  • Sea health metrics

Easy queries → nano. Hard → cloud. In-between → probabilistic.

Response format identical regardless of source. Tag validators don't care where it came from.

BLAME CRAWLER + NANO SEA = GUIDED EVOLUTION

1. Agent issues query
2. Response comes (nano sea or cloud)
3. Tag validator processes it
4. Blame Crawler attributes: which model, which nano, query type, outcome
5. Quality dimensions scored: conformance, efficiency, correctness
6. Nano quality scores guide specialization
7. Pattern recognition: "all nanos fail on reasoning" → suggests retraining
8. Suggested Jobs: "Nano quality degradation" → feeds improvement pipeline

Feedback loop drives nanos to specialize for actual usage patterns.

FLEET AGENTS + FLEET AGENTS-NANO

Fleet Agents: parallel workers in agent loop.
Fleet Agents-Nano: parallel improvement workers for nano sea.

Fleet Agents-Nano do:
  • Run cosmic cycles
  • Manage deposits
  • Analyze touch tensors
  • Adjust RBY positions
  • Generate Midwife datasets for nano training
  • Monitor sea health

Blame → Midwife → Fleet Agents-Nano → improve sea → improve responses → improve Blame.
Virtuous loop.

BUILD ORDER FOR NANO SEA INTEGRATION

Phase 1: Core (1-4 weeks)
  • Shared embedding, universal nano, swarm layer, output head
  • Milestone: Nanos generate (badly), deterministic, fast

Phase 2: Routing (1-2 weeks)
  • Router learns specialization
  • Expert crosstalk
  • Touch tensor logging
  • Milestone: Nanos activate predictably

Phase 3: Training (1-2 weeks)
  • End-to-end swarm training
  • Midwife integration
  • Milestone: Nanos actually learn

Phase 4: Lifecycle (2-3 weeks)
  • Spawner, fitness, compression, deposits
  • Cosmic cycle orchestrator
  • Milestone: Sea self-improves

Phase 5: IDE Integration (2-3 weeks)
  • Query router
  • Blame Crawler enhancements
  • Fleet Agents-Nano
  • Milestone: Agents use sea, get better

Phase 6: Mesh + Scale (3+ weeks)
  • Multi-GPU paging
  • Mesh federation
  • Production harness

WHAT NOT TO DO

1. Do NOT use old nano types (FeatureNano, PatternNano, etc). DEAD.
2. Do NOT hard-code top-k=8. Let router learn k.
3. Do NOT skip deposits. Warm-starting from random is wasteful.
4. Do NOT train all nanos equally. Specialize.
5. Do NOT ignore touch tensors. Foundation of fitness scoring.
6. Do NOT derive algorithms. Reference implementations exist. Copy, adapt, ship.
7. Do NOT route safety-critical queries to nano sea until proven in your domain.
